# FlowPilot 人工验收指南

本文面向 Maintainer 和产品 Reviewer，目标是让没有阅读 Agent 协议、测试代码或内部设计文档的人，也能直接启动并检查当前可用成果。

本文是**操作指南和验收记录模板**，不替代 [ACCEPTANCE.md](./ACCEPTANCE.md) 中的正式 Gate 标准。P0 已完成全量 Gate；实现与本文不一致时，应先核对正式验收规范、当前项目状态和设计契约，不能通过修改本文降低 Gate。

## 当前可以验收什么

**P0 — Interactive Mock Prototype 已完成全量 Gate**，本文继续提供 P0.1–P0.7 Inspector provenance 的人工走查入口和回归记录模板。当前项目阶段已进入 **E0 — Engineering Foundation**；E0 尚未开始，不能把本指南当作 E0 验收。

| 本指南可以验收 | P0 明确范围外 |
| --- | --- |
| 用自然语言表达示例意图 | 任意意图的真实 AI 理解 |
| 查看 FlowPilot 的结构化理解 | Human Takeover |
| 只在 Source 缺失时看到连接卡片 | 真实 provenance 后端与跨会话历史 |
| 体验取消、拒绝、范围不匹配和只读连接成功 | 真实 Source/InputBundle/Run 持久化 |
| 检查本次固定文章、正文和配套封面 | 真实文件/Git snapshot 与 provenance |
| 验证不可变 Mock 输入、过期、键盘和 200% 缩放边界 | 真实不可逆发布动作 |
| 查看确定性 Mock Execution 里程碑和发布前暂停 | 真实浏览器或平台发布动作 |
| 明确查看、关闭、取消或确认发布决定 | 真实平台动作与真实后置条件验证 |
| 查看经过 Mock 后置条件验证的极简结果 | 真实平台发布结果与证明 |

完成本文可以复核 **P0.1–P0.7 的人工黄金路径**；正式 P0 Gate 已由独立 Gatekeeper 逐条核对 Acceptance 1–15 并通过。本文仍不替代正式 Acceptance，未来产品变更必须重新执行适用的 Gate。

## 1. 启动原型

### 前置条件

- macOS 开发环境；
- Node.js `>=24.15.0 <25`；
- Corepack 可用；
- 当前终端目录是 FlowPilot 仓库根目录。

第一次运行时安装依赖：

```sh
corepack pnpm install
```

启动原型：

```sh
corepack pnpm dev
```

通过标准：

- [ ] 终端显示 Vite 位于 `http://127.0.0.1:43127/`；
- [ ] Electron 窗口自动打开；
- [ ] 窗口中出现“你希望 FlowPilot 做什么？”；
- [ ] 页面标明“交互原型 · 本地演示”。

`43127` 是 Electron Renderer 的本地开发端口。人工验收应在 Electron 窗口中进行。结束后在启动终端按 `Ctrl+C`。

## 2. 三分钟黄金路径

应用启动后，编辑器会预填以下确定性示例：

```text
每天早上 8 点检查我的行业学习仓库。
如果今天有新的文章，就发布到微信公众号。
正式发布之前让我确认。
```

### 步骤 A — 检查意图主页

观察首屏，不要先修改文本。

通过标准：

- [ ] 主要区域是自然语言编辑器，而不是 Dashboard 或配置表；
- [ ] 页面说明这一步不会连接数据或开始执行；
- [ ] 尚未显示“我的理解”；
- [ ] 主要动作是“分析我的意图”。

### 步骤 B — 分析意图

点击“分析我的意图”。分析期间会短暂出现“正在理解这段意图…”，随后出现“我的理解”。

通过标准：

- [ ] 原始意图文本没有被改写；
- [ ] 理解摘要显示“每天 08:00（你的时区）”；
- [ ] 数据显示“行业学习仓库 → 今天最新文章”；
- [ ] 操作显示“发布微信公众号文章”；
- [ ] 没有新内容时显示“跳过”；
- [ ] 发布之前显示“请求确认”；
- [ ] 没有出现内部 ID、cron、selector、Workflow node 或原始日志。

### 步骤 C — 检查上下文 Source 连接

“我的理解”出现后，在“数据”项内应同时出现“连接行业学习仓库”卡片。

通过标准：

- [ ] Source 连接是当前问题旁边的上下文卡片，不是永久导航或设置页；
- [ ] 卡片解释任务能力、请求范围和权限；
- [ ] 权限明确为“默认只读，不允许修改文件”；
- [ ] 页面仍明确表示尚未准备输入或开始执行。

### 步骤 D — 完成 Mock 只读连接

1. 点击“选择范围”；
2. 选择“行业学习仓库”；
3. 点击“授权所选范围”；
4. 等待“正在检查只读授权…”和“正在解析已授权的数据来源…”完成。

通过标准：

- [ ] 最终标题是“行业学习仓库已连接”；
- [ ] 范围显示“所选的行业学习 Git 仓库”；
- [ ] 权限显示“只读”；
- [ ] 显示“准备本次输入”，并明确尚未开始执行；
- [ ] 没有弹出真实文件选择器，也没有读取电脑中的真实文件。

### 步骤 E — 准备并检查本次输入

1. 点击“准备本次输入”；
2. 等待“正在选择并冻结本次输入…”完成；
3. 在“本次输入已准备”中检查文章和封面；
4. 点击“展开正文”。

通过标准：

- [ ] 数据来源是“行业学习仓库”，授权范围仍是“所选的行业学习 Git 仓库”；
- [ ] 内容版本显示“演示快照 · 固定内容版本 1”，没有伪装成真实 Git snapshot；
- [ ] 文章标题是“让自动化真正可维护：从意图到确定性执行”；
- [ ] 正文摘要和展开后的三段正文可读；
- [ ] 配套封面同时有可见预览和文字说明；
- [ ] 标题、正文、封面三个必需字段均显示“已准备”；
- [ ] 界面说明进入预览后不会静默刷新文章或封面；
- [ ] 没有显示内部 ID、完整路径或原始 hash。

### 步骤 F — 开始确定性 Mock Execution

点击“继续准备运行”。

通过标准：

- [ ] Input Preview 显示这份输入已绑定到当前模拟运行；
- [ ] 依次显示准备冻结输入、打开发布位置和准备发布动作三个有意义里程碑；
- [ ] 过程提供“停止运行准备”，但不显示滚动日志或底层 Step；
- [ ] 文章标题和固定内容版本与 Input Preview 完全一致；
- [ ] 没有打开真实浏览器、网络或微信页面。

### 步骤 G — 检查发布前暂停边界

等待标题变为“等待你的确认”。

通过标准：

- [ ] 三个准备里程碑都显示“已完成”；
- [ ] “等待发布确认”显示“已暂停”；
- [ ] 明确说明“尚未确认，也没有发布”；
- [ ] 显示“查看发布确认”，但尚未直接显示决定按钮；
- [ ] 页面没有“确认发布”或“取消发布”按钮；
- [ ] 没有成功结果、发布证明或专业 Inspector；
- [ ] 修改左侧意图后，当前暂停运行仍保留原先绑定的文章和固定输入，不会静默替换。

### 步骤 H — 明确作出发布决定

1. 点击“查看发布确认”；
2. 等待“正在复核发布决定”变为“确认发布这篇文章？”；
3. 检查动作、目的地、文章、固定输入和不可逆影响；
4. 点击“确认发布”。

通过标准：

- [ ] 复核期间“取消发布”和“确认发布”均禁用，并说明原因；
- [ ] 对话框只显示语义名称和冻结输入摘要，不显示内部 ID、账号引用或 selector；
- [ ] 对话框明确说明本原型只记录决定，不连接微信或执行发布；
- [ ] 点击确认后先显示“正在执行本地 Mock 动作”；
- [ ] 随后显示“正在验证模拟结果”；
- [ ] 验证完成前没有出现成功结果；
- [ ] 过程明确说明不连接微信、浏览器或网络。

### 步骤 I — 检查极简 Mock Result

等待标题变为“模拟发布已验证”。

通过标准：

- [ ] 结果明确说明固定的本地 Mock 后置条件已经通过；
- [ ] 同时明确说明未连接微信，也没有执行真实发布；
- [ ] 目的地、文章和固定输入与 Confirmation 完全一致；
- [ ] 成功结果保持极简，没有指标墙、日志或内部 ID；
- [ ] “检查详情”可用，但专业 provenance 在打开前不占据默认结果界面；
- [ ] 修改左侧意图后，结果仍保留原先绑定的文章和固定输入。

### 步骤 J — 按需检查 Mock provenance

1. 点击 Result 中的“检查详情”；
2. 等待“正在加载本次运行详情”变为“本次模拟运行的检查详情”；
3. 依次展开“计划与 Flow 版本”“Source 与 InputBundle”和“Run timeline”；
4. 按 `Escape` 或点击“关闭检查详情”。

通过标准：

- [ ] Inspector 明确锚定当前文章、当前终态和原冻结输入；
- [ ] 默认只展开“结果与验证”，其他专业分区按需展开；
- [ ] 可读地显示 TaskPlan、GoalPlan、Flow revision 及各自 Mock 修订；
- [ ] 显示 Source version、语义 Source、只读授权范围和不可变 InputBundle 摘要；
- [ ] Run timeline 按顺序显示冻结输入、确认、Mock action 和 postcondition；
- [ ] Inspector 不显示内部 ID、Secret、完整路径、hash、selector 或原始日志；
- [ ] 关闭后回到原 Result，“检查详情”恢复焦点；
- [ ] 打开或关闭 Inspector 不改变 Result、Source 或冻结输入。

以上全部通过，即可判定 P0.1–P0.7 黄金路径人工走查完成；P0 的独立全量 Gate 已通过，后续改动仍须按正式 Acceptance 重新验收。

## 3. 关键分支检查

这些检查用于确认失败不会被伪装成成功。每项可以独立执行；需要恢复初始状态时，重新启动 `corepack pnpm dev`。

### 3.1 空输入

1. 清空编辑器；
2. 点击“分析我的意图”。

预期：

- [ ] 显示“还不能形成可靠理解”；
- [ ] 提示先用普通语言写下结果；
- [ ] 焦点回到编辑器；
- [ ] 没有显示伪造的理解结果。

### 3.2 无法识别的意图和重试

1. 输入一段不包含示例任务必要信息的文字，例如“帮我整理内容”；
2. 点击“分析我的意图”；
3. 点击“重试分析”。

预期：

- [ ] 明确说明当前确定性原型只识别示例发布意图；
- [ ] 原文仍然保留；
- [ ] 重试不会把无法识别的文本伪装成成功。

### 3.3 分析 loading 和取消

恢复文首的完整示例，点击“分析我的意图”。如果设备上 loading 状态停留时间足够，立即点击“取消分析”。

预期：

- [ ] loading 时文本仍然可见；
- [ ] 取消后文本没有丢失；
- [ ] 焦点返回“分析我的意图”；
- [ ] 如果设备完成得太快而无法点击，此项记为“由自动测试覆盖”，不能据此判定失败。

### 3.4 修改后旧理解过期

1. 先成功形成“我的理解”；
2. 修改编辑器中的任意文字。

预期：

- [ ] 旧理解标记为“需要更新”；
- [ ] Source 卡片提示“先更新理解，再连接数据来源”；
- [ ] “选择范围”不可用；
- [ ] 系统没有使用旧理解请求新权限。

### 3.5 使用 Escape 关闭范围选择

1. 恢复并重新分析完整示例；
2. 点击“选择范围”；
3. 按 `Escape`。

预期：

- [ ] 选择器关闭；
- [ ] 没有授予权限；
- [ ] 焦点返回“选择范围”按钮。

### 3.6 取消选择或暂不授权

分别检查以下任一路径：

- 在范围选择器中点击“取消选择”；或
- 在初始 Source 卡片中点击“暂不授权”。

预期：

- [ ] 显示“还不能使用行业学习仓库”；
- [ ] 说明没有获得文件访问权限，或说明用户选择了暂不授权；
- [ ] 可以“重新选择”；
- [ ] 当前理解仍然保留。

### 3.7 范围不匹配

1. 点击“重新选择”；
2. 选择“下载文件夹”；
3. 点击“授权所选范围”。

预期：

- [ ] 明确说明该范围不包含当前意图需要的行业学习内容；
- [ ] 明确说明权限没有扩大；
- [ ] 没有继续到连接成功；
- [ ] 可以重新选择“行业学习仓库”。

### 3.8 取消连接检查

选择“行业学习仓库”并开始授权后，在 loading 阶段点击“取消连接检查”。

预期：

- [ ] 显示连接检查已取消；
- [ ] 数据来源仍未连接；
- [ ] 可以重新选择；
- [ ] 不会在后台稍后变成成功。

### 3.9 取消输入准备并恢复

1. 成功连接“行业学习仓库”；
2. 点击“准备本次输入”；
3. 在 loading 阶段点击“取消输入准备”；
4. 点击“重新准备”。

预期：

- [ ] 取消后显示“还不能准备本次输入”；
- [ ] 明确说明没有创建可继续使用的本次输入；
- [ ] 没有显示空白成功预览；
- [ ] 重新准备后可到达“本次输入已准备”。

### 3.10 冻结输入过期

1. 完成 Input Preview；
2. 修改左侧意图原文中的任意文字。

预期：

- [ ] 旧理解标记为“需要更新”；
- [ ] Input Preview 变为“这份输入已过期”；
- [ ] 界面说明旧输入仍保持原样，但不能交给后续运行；
- [ ] “继续准备运行”不再出现；
- [ ] 必须返回重新选择或重新分析，不会静默刷新旧输入。

该分支应在尚未点击“继续准备运行”时检查。一旦模拟运行已经创建，修改意图只能影响未来运行，当前运行仍绑定旧的冻结输入。

### 3.11 停止运行准备并恢复

1. 在 Input Preview 点击“继续准备运行”；
2. 在任一 loading 里程碑期间点击“停止运行准备”；
3. 点击“返回输入预览”；

预期：

- [ ] 显示“还不能准备本次运行”；
- [ ] 明确说明没有打开确认界面、没有执行或发布内容；
- [ ] 没有显示“等待你的确认”或成功结果；
- [ ] 返回后仍是原来的冻结文章和封面；
- [ ] “继续准备运行”恢复焦点，可以再次开始。

### 3.12 关闭确认不等于决定

1. 到达“等待你的确认”，点击“查看发布确认”；
2. 等待“确认发布这篇文章？”出现；
3. 分别使用 `Escape` 和右上角“关闭发布确认”关闭；

预期：

- [ ] 对话框关闭后焦点恢复到“查看发布确认”；
- [ ] 运行仍显示“等待你的确认”；
- [ ] 没有记录确认或取消决定；
- [ ] 没有执行发布，也没有进入终态。

### 3.13 明确取消发布

1. 再次打开发布确认；
2. 点击“取消发布”。

预期：

- [ ] 标题变为“本次发布已取消”；
- [ ] 显示独立的中性取消 Result，并说明没有执行任何平台动作；
- [ ] 取消只终止本次 Mock 发布边界，不显示成功；
- [ ] 取消不会自动重试或推进任何成功状态；
- [ ] 可以返回同一份 Input Preview，冻结文章和封面保持不变。

### 3.14 停止 Mock 结果验证

1. 明确确认发布；
2. 在“正在执行本地 Mock 动作”或“正在验证模拟结果”期间点击“停止模拟验证”。

预期：

- [ ] 显示“还不能验证模拟结果”；
- [ ] 明确说明没有真实发布，也没有生成成功结果；
- [ ] 可以重新验证或返回同一份 Input Preview；
- [ ] 原冻结输入保持不变。

### 3.15 检查取消结果的 provenance

1. 走显式“取消发布”分支；
2. 在中性取消 Result 中点击“检查详情”。

预期：

- [ ] 终态显示 `CANCELLED`；
- [ ] Confirmation decision 显示“已取消”；
- [ ] Mock action 与 Postcondition 均显示“未执行”；
- [ ] timeline 只记录冻结输入、明确取消和取消结果；
- [ ] 没有成功样式或虚构的动作/验证证据。

## 4. 可用性和信息边界

### 键盘

- [ ] 使用 `Tab` 和 `Shift+Tab` 可以到达编辑器及所有当前可用操作；
- [ ] 多行编辑器中的 `Enter` 只换行，不会提交；
- [ ] 按钮可用 `Enter` 或 `Space` 触发；
- [ ] 范围选择器中的 `Escape` 会关闭选择器并恢复焦点；
- [ ] Input Preview 的正文展开/收起及继续/返回操作可用键盘完成；
- [ ] Execution 的停止、返回和重试操作可用键盘完成；
- [ ] Confirmation 打开后焦点进入标题，`Tab` / `Shift+Tab` 不会离开对话框；
- [ ] `Escape` 关闭 Confirmation 并恢复触发按钮焦点，不会记录决定；
- [ ] Result 出现后焦点进入具体结果标题，“检查详情”可通过键盘打开；
- [ ] Inspector 打开时不抢走“检查详情”的焦点；首次 `Tab` / `Shift+Tab` 进入 Inspector，并保持在详情控件边界内；
- [ ] Inspector 分区按钮具有可读名称、展开状态和对应内容关系；
- [ ] `Escape` 关闭 Inspector 后，焦点恢复到 Result 的“检查详情”；
- [ ] 除非设计契约明确要求保留来源焦点（如 Inspector），新出现的理解、失败、loading 或成功标题能获得焦点。

### 200% 缩放

把 Electron 页面放大到 200%，分别检查 Confirmation、Result 和已展开的 Inspector。

- [ ] 内容重排后仍然可读；
- [ ] 主要操作和恢复路径仍然可见；
- [ ] 页面没有整体横向滚动；
- [ ] 文本没有被截断或相互覆盖。

### 默认简单、按需透明

- [ ] 默认界面没有永久 Source 管理、运行日志或技术 Inspector；
- [ ] Source 连接只在理解表明数据缺失时出现；
- [ ] 普通路径没有显示 `sourceId`、`GoalPlan`、`InputBundle`、完整本地路径、cron 或 selector；
- [ ] 连接成功、输入准备完成和开始运行是三个清楚分开的边界；
- [ ] 界面没有声称 Input Preview、Execution、等待确认或确认决定等于成功；
- [ ] Mock 成功只在本地后置条件验证通过后出现，并明确不是真实平台结果；
- [ ] 普通路径没有持续日志、内部运行 ID 或真实平台状态。
- [ ] 专业详情只在主动打开 Inspector 后出现，且仍不显示 Secret、完整路径或原始日志。

## 7. 后续如何维护

若后续修复或扩展 P0，应在同一份指南中追加：

1. 用户从哪里进入；
2. 按什么顺序操作；
3. 每一步应看到什么；
4. 至少一个诚实失败分支；
5. 哪些能力仍是 Mock；
6. 自动测试和视觉证据在哪里；
7. “本指南可以验收 / P0 明确范围外”表格如何变化。

P0.7 提供会话级、确定性且脱敏的最小 Inspector provenance，不实现真实浏览器、平台动作、Human Takeover、持久化、完整生产 Inspector 或 Repair。上述能力属于 P0 明确范围外；P0 全量 Gate 已通过，E0.1 审计已完成，审计结论见 [`docs/E0-ENGINEERING-BASELINE-AUDIT.md`](E0-ENGINEERING-BASELINE-AUDIT.md)，下一阶段执行 `work/E0.2-tooling-ci-packaging.md`。
