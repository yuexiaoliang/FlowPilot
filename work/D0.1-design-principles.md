# D0.1 — Design Principles and Interaction Hierarchy

## Role

Product/UX Builder

## Phase

D0 — Design Contract

## Goal

Create the first implementation-ready portion of FlowPilot's Design Contract: the design principles and interaction hierarchy that enforce "Simple by default. Transparent on demand."

This task should make it difficult for later implementation agents to accidentally rebuild FlowPilot as a dense traditional SaaS dashboard.

## In scope

Create:

### design/README.md
Explain:
- design artifacts are implementation contracts
- generated images are visual references, not behavioral authority
- written screen/component specs win when an image is ambiguous
- how implementation/reviewer agents should use design docs

### design/DESIGN-PRINCIPLES.md
Define operational rules for:
- Simple by default
- Transparent on demand
- Intent-first
- Natural language as control plane
- Progressive disclosure
- Contextual/ephemeral UI
- Trust without black-box behavior
- Minimal navigation
- Error/intervention clarity
- Accessibility/readability

### design/INTERACTION-MODEL.md
Define the three product surfaces:

1. Simple Surface
   - intent
   - concise understanding
   - essential next action
   - minimal success/failure state

2. Execution Surface
   - useful progress
   - confirmation
   - takeover
   - recovery

3. Inspection Surface
   - structured understanding
   - InputBundle/source provenance
   - run timeline/logs
   - GoalPlan/TaskPlan/Flow revisions
   - repair diffs

Define when information moves between layers.

Also define:
- when contextual Source connection appears
- when ambiguity UI appears
- when confirmation appears
- when Human Takeover appears
- when Inspector is offered
- what information must NOT be shown by default

## Out of scope

Do not:
- implement React/Electron UI
- create a dashboard
- add product features
- design every individual component
- redesign technology choices
- build real AI/Source/runtime functionality
- require internal IDs/DSL in user-facing surfaces

## Expected artifacts

- design/README.md
- design/DESIGN-PRINCIPLES.md
- design/INTERACTION-MODEL.md

## Constraints

The contract must preserve:
- users write semantics; system stores references
- Goal/Task/Source/Flow/Run separation
- default UI minimizes cognitive load
- professional transparency remains available
- technical detail does not become permanent visual clutter
- natural language does not become a hidden FlowPilot DSL

## Validation

Perform a written self-review:

For each principle answer:
1. What should the user see by default?
2. What stays hidden?
3. What event makes hidden information appear?
4. Where can a professional user inspect the underlying truth?
5. What would violate this principle?

Then review one concrete example:

```
每天早上 8 点检查我的行业学习仓库。
如果今天有新的文章，就发布到微信公众号。
正式发布之前让我确认。
```

Show how the information appears across:
- Simple Surface
- Execution Surface
- Inspection Surface

No code commands are required unless code is changed.

## Stop conditions

Escalate rather than guessing if:
- a decision would change PRODUCT-MODEL.md
- the Simple vs Inspection boundary cannot be resolved from current principles
- a new persistent top-level navigation area appears necessary
- the design would require a user-facing DSL
