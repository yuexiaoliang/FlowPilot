# D0.2 — 设计系统与上下文组件

## 角色

产品 / UX Builder

## 阶段

D0 — Design Contract

## 目标

定义可直接实现的视觉基础和可复用上下文 UI 原语，并遵守已验收的 D0.1 交互层级。

## 为什么现在做

D0.1 已通过 Gatekeeper 验收。下一有界切片是在屏幕规格和端到端流程之前，完成必需的设计系统和组件契约。

## 范围内

创建：

- `design/DESIGN-SYSTEM.md`
- `design/COMPONENTS.md`

设计系统契约必须定义视觉和交互基础：

- 颜色与语义状态 Token
- 字体、可读行宽、间距、尺寸、圆角、层级和密度
- 焦点、键盘、缩放、对比度、减少动态效果和状态播报规则
- 与渐进披露一致的克制动效和转场规则

组件契约必须定义可复用上下文原语的用途、位置、触发条件、内容层级、交互、无障碍和适用状态，至少包括：

- 意图编辑器和语义引用
- 理解审阅与歧义处理器
- Source 连接 / 权限选择器
- InputBundle 预览
- 确认卡
- 执行进度与恢复
- Human Takeover
- 结果和 `检查详情` 入口
- Inspector 分区、证据和修复差异

对每个适用组件说明 idle、loading、success、failure、paused 和 disabled 行为，同时不得在普通路径暴露内部 ID 或 Workflow DSL。必须明确其属于 Simple、Execution 还是 Inspection 层。

## 范围外

## 约束

- 保持“默认简单，按需透明”
- 自然语言 / Markdown 仍是创作控制面
- 用户写语义，系统保存引用
- 上下文 UI 只在当前需要观察、选择、比较、批准或介入时出现
- 专业细节必须可检查，但不能变成永久杂乱内容
- 不得要求用户使用 ID、cron、选择器、工作流节点或隐藏 DSL
- 书面契约是行为权威；视觉参考不能覆盖它
- 长期文档使用简体中文，并直接保存在稳定主路径

## 验收映射

验收映射：D0 标准 9 和 14；同时复查标准 2、6–8、13，以及全局完成定义中的产品一致性与文档要求。

## 验证

- 对照 `DESIGN-PRINCIPLES.md` 和 `INTERACTION-MODEL.md` 审查每个 Token 和组件
- 验证每个所列组件都有显式触发条件、层级位置和所有适用状态
- 验证已规定键盘、焦点、缩放、对比度、减少动态效果和状态播报行为
- 验证默认界面不要求或暴露 ID、DSL、原始日志或密集 Dashboard 结构
- 验证文档使用简体中文且语义完整
- 执行仓库文本检查，确认产物非空且没有尾随空白

## 停止条件

遇到以下情况时停止并升级：

- 组件决策会改变 Goal、Task、Source、InputBundle、Flow 或 Run 语义
- 必须增加新的永久顶层目的地
- 某个状态无法一致地归入 Simple、Execution 或 Inspection
- 组件会要求用户使用 DSL 或造成隐藏权限扩张
