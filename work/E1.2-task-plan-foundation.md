# E1.2 — Task source / TaskPlan 基础编译切片

## 角色

Builder

## 阶段

E1 — Intent Compiler

## 目标

在已验收的 `@flowpilot/goal-ir` 边界上，建立一个最小、provider-neutral、deterministic 的普通 Markdown Task source → schema-validated versioned TaskPlan 闭环。用户继续编辑自然语言；系统保存独立的 Task source revision 和 compiled TaskPlan revision。

## 为什么现在做

E1.1 Goal source / GoalPlan 已由独立 Gatekeeper 验收。`DEVELOPMENT-PLAN.md` 的下一项是 Task source / revision 与 TaskPlan schema；本切片只建立 Task 的稳定 domain / schema / fake provider 边界，不把 Source、调度执行或 Workflow runtime 提前拉入范围。

## 范围内

- 建立独立的 Task source、Task source revision、TaskPlan revision 和 schema version；不得把 Goal 当作 Task 的别名。
- 定义 TaskPlan v1，覆盖用户意图、与 Goal 的 typed semantic reference、自然语言 trigger / timing 的结构化表达、Source / selection 的语义描述和 Task policy；实际 Source authorization / resolution 仍留在 E2。
- 提供 provider-neutral `StructuredTaskProvider` 与 fake / deterministic fixture provider；provider 不访问网络或真实 credential。
- 将普通 Markdown Task fixture 编译为 schema-validated TaskPlan；source 文本必须保持可读，不要求用户写内部 ID、`@goal/...`、`@source/...`、UUID、cron 或 selector。
- source 修改产生新的 source / compiled-plan revision；旧 source 与旧 plan 保留并可按 revision 审计。使用 SHA-256 source hash 和 UTC ISO-8601 时间，保持 source revision 与 plan revision 独立 append-only。
- 对 schema-invalid、schema-valid 但 policy-unsafe、unsupported version、stale revision 和 provider failure 返回 typed failure，不静默覆盖旧记录或隐藏回退。
- 增加 domain / schema / compatibility / compiler / revision tests，并在 handoff 中记录 E1 Acceptance 映射。

## 范围外

- 不实现 Source provider、权限授权、Source resolve、InputBundle、Git / 文件系统读取或任何生产数据访问。
- 不实现 scheduler、missed-schedule 执行、Run、idempotency、Workflow Runtime、BrowserDriver、Repair 或 Human Takeover runtime。
- 不实现完整 semantic entity resolver、ambiguity UI 或真实 Goal / Source 绑定；TaskPlan 中的 reference 只能使用可校验的 fixture / boundary 表达，不能凭空生成稳定实体。
- 不实现 SQLite persistence、Electron / React / IPC 变更或新的信任边界。
- 不接入真实 AI provider、网络、平台账号或生产 credential。

## 预期文件 / 产物

- 与 `@flowpilot/goal-ir` 依赖方向一致的 Task IR / compiler package。
- Task source / TaskPlan v1 schema、provider boundary、deterministic provider、typed errors 和 in-memory revision store。
- natural-language Task fixture、timing / semantic reference fixture、revision audit 与 invalid-output tests。
- 必要的中文 handoff；不修改 `docs/ACCEPTANCE.md` 或 `docs/DEVELOPMENT-PLAN.md`。

## 约束

- TypeScript strict；provider、持久化边界和所有不可信结构化输出必须经过 runtime schema validation。
- source 文本是面向人的事实源；compiled TaskPlan 是版本化产物，不能反过来成为用户 DSL。
- Goal、Task、Source、InputBundle 必须保持分离；内部 ID 只在系统边界使用，不能要求用户提供。
- timing 只做确定性结构化解释，并显式保留 timezone；不把 cron 暴露为用户输入，也不实现调度执行。
- 无 ADR 不得改变 Electron、WebContentsView、IPC、持久化或信任边界。

## 验收映射

- E1 Acceptance 2：Task 可以写成普通 Markdown。
- E1 Acceptance 3：普通路径不要求内部 ID、DSL 或 cron。
- E1 Acceptance 5：Task source 编译成 schema-validated versioned TaskPlan。
- E1 Acceptance 8：Task source 离开 FlowPilot 后仍然可读。
- E1 Acceptance 9–10：修改 Task source 生成新 compiled-plan revision，旧 revision 可审计。
- E1 Acceptance 11–13：provider-neutral boundary、fake / deterministic provider 和 invalid / unsafe output rejection。
- E1 Acceptance 6–7：本切片只保留 typed semantic-reference boundary；完整稳定实体解析与 ambiguity clarification 仍需后续 bounded slice。
- Global Definition of Done：strict typecheck、相关测试、typed failure、文档和 handoff。

## 验证

至少实际执行：

```text
corepack pnpm install --frozen-lockfile
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm format:check
corepack pnpm ci:validate
corepack pnpm test
corepack pnpm build
corepack pnpm test:e2e
git diff --check
```

另外必须提供：

- natural-language Task fixture → TaskPlan 证据，包含 timing / timezone 的结构化结果；
- modified source → revision N+1，revision N 的 source 与 plan 仍可审计；
- invalid / unsafe structured output → typed rejection，旧 accepted revision 不被覆盖；
- no real provider / network / credential 证据。

## 停止条件

- Task 与 Goal 的边界或 semantic reference 需要无法由现有规范解决的产品决策；
- 需要改变 Goal IR 兼容性、持久化模型、Source authorization、IPC / trust boundary 或增加 ADR；
- schema / provider 设计开始承担 Source resolve、InputBundle、调度执行、Workflow 或 Repair 语义；
- 需要真实 AI、真实平台、网络或生产 credential 才能验证。
