# E1.1 — Goal source / GoalPlan 基础编译切片

## 角色

Builder

## 阶段

E1 — Intent Compiler

## 目标

建立一个最小、provider-neutral、deterministic 的 Goal source → schema-validated versioned GoalPlan 闭环。用户仍然编辑普通 Markdown / 自然语言；系统保存 source revision 和可审计的 compiled plan revision。

## 为什么现在做

E0 Engineering Foundation 已由独立 Gatekeeper 完成全量验收，当前阶段进入 E1。E1 规范先定义 Goal，再扩展 Task；本切片只建立 Goal 的稳定 domain / schema / fake provider 边界，为后续 Task、Source 和语义解析切片提供可测试基础。

## 范围内

- 定义 Goal source、source revision、GoalPlan revision 和稳定的 domain 类型。
- 定义并 runtime-validate GoalPlan schema，至少覆盖 intent、required / optional inputs、success / non-success criteria、human confirmation / intervention policy。
- 提供 provider-neutral structured compiler interface 和 fake / deterministic provider；当前不连接真实模型。
- 将自然语言 / Markdown fixture 编译为 GoalPlan，并保留原 source 可读性。
- 修改 source 后产生新的 compiled-plan revision，旧 revision 仍可读取 / 审计。
- 对 invalid / unsafe structured output 返回 typed failure，不静默接受或降级。
- 增加 domain / schema / compatibility / compiler tests，并记录 Acceptance 映射和 handoff。

## 范围外

- 不实现 Task source / TaskPlan、schedule、Source reference 或 selection rule。
- 不实现 Source、InputBundle、SQLite persistence、Workflow Runtime、BrowserDriver、Repair、Human Takeover runtime 或真实平台。
- 不要求用户编写 `@goal/...`、`@source/...`、UUID、cron、selector 或内部 DSL。
- 不接入真实 AI provider，不把 provider SDK 类型泄漏到 domain / renderer。
- 不修改已验收的 D0 / P0 / E0 行为或设计契约。

## 预期文件 / 产物

- 与现有 workspace 依赖方向一致的 Goal domain / IR module。
- GoalPlan schema、compiler boundary、fake provider 和 typed errors。
- natural-language fixture、revision / invalid-output 测试。
- 必要的中文规范 / handoff 更新。

## 约束

- TypeScript strict；外部、持久化和 provider 输出必须 runtime schema validation。
- source 文本是面向人的事实源；compiled plan 是版本化产物，不能反过来成为用户 DSL。
- Goal 与 Task、GoalPlan 与 TaskPlan 必须保持分离；内部 ID 只在系统边界使用。
- deterministic provider 不得调用网络或真实 credential；失败必须是 typed、可行动的结果。
- 没有 ADR 不得改变 Electron、WebContentsView、IPC、持久化或信任边界。

## 验收映射

- E1 Acceptance 1：Goal 可以写成普通 Markdown。
- E1 Acceptance 4：Goal source 编译成 schema-validated versioned GoalPlan。
- E1 Acceptance 8：面向用户文本离开 FlowPilot 后仍可读。
- E1 Acceptance 9–10：source 修改产生新 compiled-plan revision，旧 revision 可审计。
- E1 Acceptance 12–13：fake / deterministic compiler provider 支持 CI，invalid structured output 被拒绝。
- Global Definition of Done：strict typecheck、相关测试、typed failure、文档和 handoff。

## 验证

至少实际执行：

```text
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm format:check
corepack pnpm test
corepack pnpm build
corepack pnpm test:e2e
git diff --check
```

另外必须提供：

- natural-language fixture → GoalPlan 证据；
- modified source → revision N+1，revision N 仍可审计；
- invalid / unsafe structured output → typed rejection；
- no real provider / network / credential 证据。

## 停止条件

- Goal 与 Task 的边界出现无法由现有规范解决的产品歧义；
- 需要改变锁定架构、持久化模型、IPC / trust boundary 或增加 ADR；
- schema / provider 设计开始提前承担 Task、Source、Workflow 或 Repair 语义；
- 需要真实 AI、真实平台、网络或生产 credential 才能验证。
