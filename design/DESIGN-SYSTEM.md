# FlowPilot 设计系统

本文件是 D0.2 的视觉与交互基础契约。它把 `DESIGN-PRINCIPLES.md` 与
`INTERACTION-MODEL.md` 中的层级规则变成可实现、可检查的令牌和行为约束。
它不新增产品实体、导航目的地或运行时语义；后续屏幕规格和实现必须引用本文件。

## 1. 不变项

FlowPilot 的产品不变量是：

> 默认简单，按需透明。

设计系统必须让用户先看到自己想要的结果、FlowPilot 的简洁理解或当前状态；只有当用户需要观察、选择、比较、批准或介入时，才出现上下文 UI。视觉稿、原型和实现细节不能覆盖这些规则。

三个界面层级使用同一套令牌，但密度和可见信息不同：

| 层级 | 默认密度 | 令牌使用约束 |
| --- | --- | --- |
| Simple | 宽松、单一主线 | 以自然语言、语义名称和一个主要下一步为主；不显示内部 ID、DSL、cron、selector、工作流节点或原始日志。 |
| Execution | 适度、状态优先 | 只显示当前里程碑、具有后果的输入、确认/接管/恢复动作；不变成持续滚动的 Dashboard。 |
| Inspection | 信息密度可提升 | 使用分区、版本关系和已脱敏证据解释当前对象；从上下文进入，关闭后回到来源并恢复焦点。 |

令牌命名使用“语义角色”而不是组件专属颜色。组件只能引用角色令牌，不能自行发明看似相同的蓝色、红色或阴影。颜色值是浅色桌面主题的基线，若未来增加主题，必须保持相同语义、对比度和状态冗余。

颜色规则：

1. 普通正文和操作标签至少达到 WCAG AA 的 4.5:1；大文字至少达到 3:1。交互边界、焦点环和非文字状态指示至少达到 3:1。
2. 成功、失败、警告、暂停、加载和禁用必须同时有可读文字、语义图标或形状、以及状态区域；颜色不能是唯一差异。
3. 红色只表示危险/失败，紫色只表示暂停/人工介入；不能用红色表示“需要用户确认”而不说明原因。
4. 禁用控件不能仅靠降低透明度区分。它必须有不可操作的样式、可读的原因，且不能成为键盘焦点目标；若用户需要知道原因，原因应在相邻文字中可读，而不是只在悬停提示中出现。
5. 远程网页内容使用其隔离的浏览器上下文；不得把远程页面的颜色当作 FlowPilot 状态令牌。

## 3. 字体与可读性

### 3.1 字体令牌

默认使用系统字体，避免下载字体造成首屏等待或网络依赖。中文和英文应在同一层级保持相近的视觉重量。

| 令牌 | 规格 | 用途 |
| --- | --- | --- |
| `font.family.ui` | `-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Microsoft YaHei", sans-serif` | 所有普通 UI 与自然语言内容。 |
| `font.family.mono` | `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` | 仅 Inspector 中的哈希、事件字段或结构化值；不出现在普通路径。 |
| `font.size.body` | `16px` | 意图、正文、状态说明。 |
| `font.size.body-small` | `14px` | 控件标签、辅助说明；不可用于长篇主要内容。 |
| `font.size.title` | `28px` / `1.25` | 当前工作区标题；不使用巨型营销标题。 |
| `font.size.section` | `20px` / `1.35` | 区段标题或卡片标题。 |
| `font.size.subsection` | `16px` / `1.5` | 组标题。 |
| `font.size.meta` | `13px` / `1.45` | 时间、来源状态等次要元数据；不承载唯一决策。 |
| `font.weight.regular` | `400` | 正文。 |
| `font.weight.medium` | `500` | 标签、按钮、状态标题。 |
| `font.weight.semibold` | `600` | 页面标题和关键结果；不大面积使用。 |
| `font.line.body` | `1.65`（中文可到 `1.75`） | 正文和意图编辑。 |
| `font.line.compact` | `1.4` | 控件和单行状态；不得用于长正文。 |

### 3.2 行宽和层级

- 意图编辑器、理解摘要和结果说明的正文最大宽度为 `68ch`，推荐 `60–66ch`；长中文段落不超过 `42` 个汉字左右的视觉行宽。
- 单条状态/错误说明最大宽度为 `60ch`；原因与下一步不要被并排挤压到难读。
- Inspector 结构化文本最大宽度为 `72ch`；表格或差异区域可以横向滚动，但普通解释不应依赖横向滚动。
- 标题、当前状态、主要操作、次要说明、可检查入口按此顺序建立层级。相邻层级至少有一个字号、字重或间距差异，不只靠颜色。
- 重要文本不得全部大写、字距不得以压缩为获得更多信息；中文不强制字母式大写样式。
- 用户输入中的 Markdown 标题可以保留语义，但不得让 Markdown 语法本身成为唯一层级线索；渲染文本必须仍然可读。

## 4. 间距、尺寸与密度

### 4.1 间距令牌

基础单位为 `4px`。实现只使用下列语义间距，避免每个组件产生一套局部数值。

| 令牌 | 值 | 典型用途 |
| --- | ---: | --- |
| `space.0` | `0px` | 无间距。 |
| `space.1` | `4px` | 图标与标签的最小间距。 |
| `space.2` | `8px` | 同组控件、标签与输入。 |
| `space.3` | `12px` | 行内状态、紧密摘要。 |
| `space.4` | `16px` | 默认控件组、卡片内边距的最小值。 |
| `space.5` | `20px` | 相关内容块。 |
| `space.6` | `24px` | 卡片内边距、主要段落间距。 |
| `space.8` | `32px` | 工作区区段、桌面横向内边距的基线。 |
| `space.10` | `40px` | 页面主要区段间距。 |
| `space.12` | `48px` | 工作区顶部/底部呼吸空间。 |
| `space.16` | `64px` | 大区段分隔；默认路径少用。 |

间距规则：

- 相关内容使用小间距，不相关区段使用大间距；用空间表达分组而不是增加分隔线。
- Simple 默认使用 `space.6` 卡片内边距和 `space.8` 工作区内边距，避免密集控制台感。
- Execution 可在状态卡中使用 `space.4–space.6`；同一屏最多一条主要进度线和一个当前上下文卡片。
- Inspection 可以使用 `space.3–space.5` 的结构化行间距，但不得把高密度布局回流到 Simple 或 Execution。

### 4.2 操作尺寸

| 令牌 | 值 | 规则 |
| --- | ---: | --- |
| `size.control.min-height` | `44px` | 所有主要按钮、输入和可操作行的最低高度。 |
| `size.control.compact-height` | `36px` | 只用于 Inspector 内次要工具；仍需有可见标签/焦点，不用于唯一关键操作。 |
| `size.icon-action` | `44 × 44px` | 图标按钮的可点击区域；图标本身可以是 20–24px。 |
| `size.chip` | `32px` 高 | 仅作信息/选择摘要；不能承担唯一的关键操作。 |
| `size.focus-outline` | `2px` | 键盘焦点外环；另加 2px 内缘。 |
| `layout.shell-max` | `1200px` | 桌面工作区内容最大宽度，避免超宽行。 |
| `layout.inspector` | `360–440px` | 侧向检查区域的舒适宽度；空间不足时转为同上下文的面板/抽屉。 |

控件操作目标不能小于 `44 × 44px`，除非它是非操作的装饰或位于拥有等价大操作目标的文本流中。触控/高缩放时不得通过压缩文字来保持一行；内容应重排。

### 4.3 圆角、边框与层级

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `radius.control` | `8px` | 输入、按钮、选择行。 |
| `radius.card` | `12px` | 理解摘要、输入预览、结果卡片。 |
| `radius.sheet` | `16px` | 上下文面板、Inspector 抽屉。 |
| `radius.pill` | `999px` | 状态徽标、短摘要；不用于长文。 |
| `border.width.default` | `1px` | 默认边界。 |
| `border.width.emphasis` | `2px` | 焦点、选中或高风险状态；配合文字/图标。 |

层级只使用四层，不以阴影模拟永久 Dashboard：

| 层级令牌 | 建议值 | 内容 |
| --- | ---: | --- |
| `elevation.content` | `none` | 普通工作区和区段。 |
| `elevation.card` | `0 1px 2px rgba(23,32,42,.06)` | 与画布轻微分离的卡片。 |
| `elevation.context` | `0 8px 24px rgba(23,32,42,.12)` | 当前需要的上下文面板/浮层。 |
| `elevation.modal` | `0 16px 40px rgba(23,32,42,.18)` | 确认或接管等需要聚焦的模态层。 |

层叠顺序按 `content → context → inspection → modal/takeover`。Inspection 应保持可关闭和有来源锚点；阴影、遮罩或层叠顺序不能代替标题、焦点和状态文字。

## 5. 状态、焦点与键盘

### 5.1 通用状态语言

所有组件只呈现对当前决策有意义的状态。`—` 表示该组件在该状态下不渲染或不是该组件的语义，不得为完整矩阵添加空占位。

| 状态 | 语义 | 视觉/文案规则 |
| --- | --- | --- |
| `idle` | 等待用户输入或等待当前上下文动作 | 保持轻量、可操作；不显示“空日志”或无意义的旋转。 |
| `loading` | 正在进行已说明的理解、解析、授权、快照或验证 | 显示动词和对象，例如“正在准备本次输入”；保留已输入内容和取消/返回能力（若安全）。 |
| `success` | 该组件负责的条件/事件已被验证 | 使用结果文字；运行成功必须等待后置条件，不以点击无异常代替。 |
| `failure` | 已知条件失败或不可继续 | 说明影响、证据入口和允许的下一步；不得把未知状态装成失败后的自动成功。 |
| `paused` | 等待确认、人工接管、重试窗口或安全判定 | 明确暂停原因和交还/恢复条件；不与成功混用。 |
| `disabled` | 因权限、策略、依赖或当前层级不可操作 | 说明原因；不可操作元素通常不进入 Tab 顺序，仍要能读到原因。 |

### 5.2 焦点

- 所有可操作元素必须有可见焦点环：`2px` `color.focus.ring` 外环加 `2px` 与背景形成内缘；不能只依靠浏览器默认的低对比轮廓。
- 上下文 UI 出现时，焦点移到其标题或第一项可安全操作控件，并在关闭/解决后恢复到触发它的元素。Focus 变化不得让用户失去未保存意图。
- 确认卡、Human Takeover 和需要决策的模态层暂时约束焦点在当前层；关闭、取消或完成后按来源恢复。非模态的 Inspector 不得抢焦点。
- 焦点顺序与视觉阅读顺序一致：标题/说明 → 当前输入或选项 → 主要操作 → 次要操作 → 检查详情。不能把隐藏技术详情插入普通 Tab 顺序。
- 焦点状态必须在 200% 缩放、深色远程页面旁和状态色背景上保持可见。

### 5.3 键盘

- 所有主要动作可通过 `Tab`、`Shift+Tab`、`Enter` 或 `Space` 完成；文本编辑器保留常见编辑、中文输入法和 Markdown 快捷键。
- 单选/多选列表用方向键移动，`Space` 选择，`Enter` 提交（仅在文案明确表示提交时）；不要要求用户使用内部值。
- `Escape` 关闭当前上下文面板、取消未提交选择或退出 Inspector；对不可逆动作不把 Escape 当成确认。
- `Enter` 不得在焦点位于多行编辑器时意外提交意图。编辑器应提供明确的分析/保存操作。
- 不把悬停、拖拽或精确指针动作作为唯一操作路径；拖拽必须有键盘等价路径。
- 快捷键不能覆盖平台/浏览器安全操作，也不能在远程网页上下文中注入未授权命令。

## 6. 缩放、重排与对比度

- 设计和实现必须在 100%、125%、150% 和 200% 文本/界面缩放下可用。200% 时正文仍可读，控件可访问，主要操作不会被裁切或被浮层遮住。
- 容器在高缩放或窄宽度时从双栏重排为单栏；不要用缩小字体或强制横向滚动保存布局。只有差异表、哈希等 Inspection 结构化内容可以在明确标注的区域横向滚动。
- 浏览器/系统文字放大不得被 `overflow: hidden`、固定行高或图片文字抵消。图片/截图必须有文字说明或同等文本证据。
- 默认颜色组合遵循 WCAG AA：普通正文 4.5:1，大文字 3:1，关键非文字边界/焦点至少 3:1。高对比度系统模式不得被硬编码背景禁用。
- 信息颜色、图标和状态文字必须三重冗余中的至少两种同时存在（文字 + 形状/图标 + 颜色）；成功、失败、暂停和需要操作的提示至少有明确的文字。
- 远程页面内容的对比度由页面负责；FlowPilot 的状态/操作层必须拥有独立表面、边界和焦点，不可与不可信页面混为一体。

## 7. 减少动态效果与播报

### 7.1 动效与转场

动效只解释上下文连续性，不用于拖延、装饰或持续吸引注意力。默认规则：

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `motion.duration.quick` | `120ms` | 悬停、按下、焦点颜色。 |
| `motion.duration.standard` | `180ms` | 展开/收起、面板进入。 |
| `motion.duration.context` | `240ms` | 上下文面板或 Inspector 转场。 |
| `motion.easing.standard` | `cubic-bezier(.2,.8,.2,1)` | 透明度/位移的小幅变化。 |

- 只动画 `opacity`、小幅 `transform` 和颜色；不得动画内容尺寸、页面高度或文字字号造成跳动。
- 上下文面板从触发元素附近进入，位移不超过 `16px`；不可逆确认、Human Takeover 和失败状态不得用长动画阻塞操作。
- 加载状态可以有低幅度、可停止的指示，但必须同时显示文字；不使用无限滚动日志、自动轮播或闪烁警示。
- 尊重 `prefers-reduced-motion: reduce`：所有非必要位移、缩放、弹跳和循环动画改为即时显示或低频透明度变化；状态和焦点不能因减少动效而消失。
- 动效不能是完成、成功或失败的唯一证据；验证文本和状态结构始终存在。

### 7.2 状态播报

- `loading`、里程碑进度和成功/跳过/失败结果放入单一 `aria-live="polite"` 区域，使用短句且只播报状态变化，不重复整块内容。
- 安全暂停、确认请求、Human Takeover 和未知/不可恢复失败在用户当前上下文可见并播报；需要立即行动的单一消息才可使用 `assertive`，不可连续抢占屏幕阅读器。
- 进度更新按用户可理解的里程碑播报，如“正在准备输入”“等待你的确认”“正在验证结果”，而不是每个内部 Step/事件。
- 错误文字与输入/操作通过 `aria-describedby` 或等价语义关联；焦点移动到可修复问题时，先播报原因再提供操作。
- 页面变化后不得只播报“完成”而隐藏具体结果；成功、跳过、暂停和失败使用不同文字，不把 `SKIPPED` 伪装成成功。
- 屏幕阅读器可访问与视觉界面相同的自然语言理解、权限范围、输入摘要、确认事件和检查入口。内部 ID、原始日志或 Secret 不因播报而泄漏到普通路径。

## 8. 实现检查表

任何采用本设计系统的切片，在评审前必须回答：

1. 默认路径是否只依赖语义名称和自然语言，而没有 ID、DSL、cron、selector、工作流节点或原始日志？
2. 当前组件属于 Simple、Execution 还是 Inspection；为什么现在需要它？
3. 每个颜色是否有文字/图标/形状冗余，且符合对比度要求？
4. 键盘、焦点恢复、200% 缩放和 `prefers-reduced-motion` 下是否仍可完成同一目标？
5. `success` 是否代表已验证条件，而不是“按钮没有报错”？`failure`、`paused` 和 `disabled` 是否清楚区分？
6. 当前状态结束后，临时 UI 是否消失，详情是否仍可从 `检查详情` 进入？

本文件不规定具体屏幕构图、导航标签或端到端流程；这些属于后续 `SCREEN-SPECS.md` 与 `FLOWS.md`，且不得弱化本文件的令牌和可访问性约束。
