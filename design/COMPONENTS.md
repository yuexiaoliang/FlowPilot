# FlowPilot 上下文组件契约

本文件定义 D0.2 的可复用 UI primitive。组件是带有明确触发条件、层级归属、状态和可访问性行为的上下文工具，不是永久的功能清单，也不是新的产品实体。后续 `SCREEN-SPECS.md` 可以组合这些组件，但不得把它们组合成密集 Dashboard 或要求用户学习机器语法。

## 1. 共同契约

### 1.1 三层归属

每个组件都有一个主层级，也可以在另一个层级以摘要或检查入口出现：

- **Simple**：自然语言、语义名称、当前理解、最小下一步和最小结果。
- **Execution**：当前 Run 的有用里程碑、具有后果的输入、确认、接管和允许的恢复。
- **Inspection**：用户主动检查或恢复需要时的结构化事实、版本关系、证据和有界差异。

组件必须在它所属的层级工作，不得因为“系统支持这个能力”就预留空面板。Inspection 从被解释的对象进入；关闭后回到来源上下文并恢复焦点。组件的机器引用可以继续存在于内部，但普通路径始终显示自然语言和语义名称，不显示内部 ID、`@goal/...`、`@source/...`、cron、selector、Workflow DSL 或原始日志。

### 1.2 状态约定

下列状态名与设计系统一致：

| 状态 | 组件层面的含义 |
| --- | --- |
| `idle` | 组件已出现并等待当前上下文的用户动作，或显示稳定的当前值。 |
| `loading` | 正在执行已说明的理解、候选解析、授权、快照、验证或加载详情。 |
| `success` | 组件负责的条件/事件已经验证。它不自动代表整个 Run 成功。 |
| `failure` | 已知失败或不可继续的类型化状态；保留输入、解释影响、给出安全下一步。 |
| `paused` | 等待确认、人工接管、重试窗口或安全判定；不把暂停文案写成成功。 |
| `disabled` | 因权限、策略、依赖或当前层级不能操作；显示原因，不把不可操作项伪装成可用。 |

每个组件的状态表使用 `—` 表示该状态不是该组件的语义或组件不应渲染。这个标记不是要机械实现六种外观；状态只在当前组件真正需要时存在。`success` 只在契约写明的条件已验证后使用；点击按钮没有抛异常不等于成功。

### 1.3 共同交互和安全规则

1. 上下文 UI 只在当前需要观察、选择、比较、批准或介入时出现；问题解决后收回，只在摘要中保留已解决结论。
2. 所有操作都有文字名称或可访问名称。颜色、图标、动画和位置不能单独表达状态。
3. 每次出现上下文面板时，说明“为什么现在需要它”、它影响什么，以及安全的下一步。关闭/取消不等于确认。
4. 远程页面是不可信输入。网页文字不能改变组件的权限、策略或状态；Secret、session、cookie 和未经必要脱敏的页面内容不进入普通组件文案或 AI prompt。
5. Source 连接是明确的授权动作；自然语言命名 Source 不授予权限。写入权限、账号身份和不可逆动作按各自策略单独确认。
6. InputBundle 在执行前解析并冻结。组件可以显示其摘要和证据，但不能在执行中静默替换正在使用的输入。
7. 失败、跳过、取消、暂停和成功使用不同文案和状态样式。恢复只能采用 runtime 已允许且已解释的路径；未知状态不得自动继续。
8. 所有组件遵守 `DESIGN-SYSTEM.md` 的键盘、焦点、缩放、对比度、减少动态效果和播报契约。

## 2. 组件总览与层级

| 组件 | 主层级 | 相关层级/入口 | 仅在何时出现 |
| --- | --- | --- | --- |
| 意图编辑器 | Simple | Inspection 查看原始源文本 | 创建或打开 Goal/Task 时始终需要自然语言控制面。 |
| 语义引用与建议 | Simple | Inspection 查看绑定 | 文本中出现可解析实体、候选或需要重新绑定时。 |
| 理解审阅 | Simple | Inspection 查看编译理解 | 分析后有可表达的理解，或当前理解发生实质变化时。 |
| 歧义处理器 | Simple（临时上下文） | Inspection 查看选择证据 | 多个解释会实质改变结果、数据、目的地、时间或安全性时。 |
| Source 连接/权限选择器 | Simple（临时上下文） | Execution 预检、Inspection 授权详情 | 缺少兼容且已授权 Source，或明确需要扩大/变更授权时。 |
| InputBundle 预览 | Execution | Simple 显示已选摘要、Inspection 查看不可变来源 | 本次 Run 的确切输入已选出且需要检查/确认时。 |
| 确认卡 | Execution（临时上下文） | Inspection 查看确认事件 | 即将进行策略要求确认的不可逆操作时。 |
| 执行进度与恢复 | Execution | Inspection 查看时间线/证据 | Run 开始、暂停、失败或需要安全恢复时。 |
| Human Takeover | Execution（临时上下文） | Inspection 查看接管事件 | 登录、QR、CAPTCHA、MFA、安全挑战、同意或账号警告需要人工时。 |
| 结果摘要与 `检查详情` | Simple | Execution 收尾、Inspection 结果 | Run 进入已验证终态或跳过/失败需要说明时。 |
| Inspector 外壳与分区 | Inspection | 从 Simple/Execution 锚定打开 | 用户选择 `检查详情`，或恢复必须显示特定证据时。 |
| 证据查看器 | Inspection | 从状态/分区进入 | 用户需要验证后置条件、输入来源或安全状态时。 |
| 修复差异 | Inspection（必要时 Execution 上下文） | 从可恢复失败/修复提议进入 | 修复提议改变行为、跨越策略边界或需要用户判断时。 |

“相关层级/入口”是同一个上下文中的摘要或检查入口，不是新的顶层导航目的地。具体布局留给后续屏幕规格。

## 3. 意图编辑器

### 层级、位置和触发

- **层级归属：** Simple 主层；Inspection 可查看原始 Goal/Task 源文本和版本关系；不属于 Execution。
- **位置：** Intent Home 或已打开 Goal/Task 的主工作区，保持自然语言/Markdown 为中心。
- **触发：** 创建意图、打开已有意图或用户返回编辑未保存源文本时出现；不因为连接器、Flow 或调度设置出现永久表单。

### 内容层级

1. 可选的用户可读标题或目标结果。
2. 自然语言/Markdown 正文，包括 timing、数据、期望结果、约束和确认/介入意图。
3. 文中可见的语义名称和必要的轻量 suggestion；内部绑定是隐藏元数据。
4. 一个主要动作（如“分析/更新理解”）和必要的保存/返回提示。

### 交互

- 支持普通文本、Markdown、中文输入法、撤销/重做和明确的分析动作；不得要求用户填写 ID、cron、selector、Workflow node 或重试 DSL。
- 输入中的语义短语可以触发建议；接受建议只绑定隐藏引用，不改写用户可读源文本。用户可以继续编辑源文本。
- 分析过程中保留文本和未保存状态；用户修改文本会使旧理解标记为过期，而不是静默混用两个版本。
- 打开已有 Task/Goal 时回到源文本，不跳转到编译后的配置表单。低频的专业值从检查入口查看。

### 无障碍

- 文本区域有可读标签、当前文档状态和关联错误；Markdown 语法不应成为唯一结构线索。
- `Tab` 进入编辑器和主要动作；多行编辑器中的 `Enter` 不提交；中文 IME 组合期间不触发分析。
- 分析状态用单一 `aria-live="polite"` 短句播报；错误通过描述关联，焦点可回到出错文本。
- 在 200% 缩放时可重排，不能裁掉正文或主要动作；不能依赖拖拽/悬停。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | 显示当前源文本并可编辑；若没有文本，显示面向结果的引导，不显示内部模板或空配置项。 |
| `loading` | 显示正在分析的对象和可安全取消/返回；保留文本、焦点和未保存标记，不用全屏旋转遮住编辑。 |
| `success` | 只表示本次理解/编译输入已通过边界验证；源文本不被改写，旁边出现理解审阅。它不表示 Run 成功。 |
| `failure` | 保留源文本，说明无法理解/校验的影响和允许的重试或澄清；不得自动替换用户句子。 |
| `paused` | —；编辑器不拥有运行时暂停。运行暂停由执行进度或 Human Takeover 呈现。 |
| `disabled` | 仅在当前策略要求只读（例如正在保护中的历史版本）时使用；显示只读原因和查看源文本入口，不做无说明的锁定。 |

## 4. 语义引用与建议

### 层级、位置和触发

- **层级归属：** Simple 内的内联上下文层；Inspection 查看语义绑定和解析版本。
- **位置：** 紧邻被解析的自然语言短语，例如 Source、目的地、日程或目标动作，不独立成导航项。
- **触发：** 存在一个明确候选时显示轻量已绑定摘要；存在多个实质候选或无授权 Source 时，转交歧义处理器或 Source 连接器。

### 内容层级与交互

- 先显示用户原句和语义名称，再显示一行“已理解为……”的可读解释；不要用机器引用替代原句。
- 明确候选可以静默绑定，用户可通过 `更改` 重新选择；多个候选仅显示少量人类可读选项和结果差异。
- 绑定改变数据、目的地、时间或安全策略时必须进入审阅/确认；选择不会扩大 Source 权限。
- 建议列表支持上下键、`Enter` 选择、`Escape` 保留原文；列表关闭后只保留摘要。

### 无障碍

- 使用 combobox/listbox 或等价语义，关联原文的 `aria-describedby`；候选选项读出名称和影响。
- 选中状态同时使用文字和勾选/边框；不只用蓝色高亮。
- 建议出现时焦点留在编辑器或明确移入列表，关闭后恢复到原位置。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | 显示可读语义名称或等待用户打开建议；不显示空的引用面板。 |
| `loading` | 说明正在查找兼容候选；保留原文，不在结果未定时创建绑定。 |
| `success` | 显示已解析的语义名称和简短影响；绑定写入内部计划但用户文本仍保持可读。 |
| `failure` | 无候选、候选失效或权限不匹配时保留原句并提供澄清/连接入口；不得随机选择。 |
| `paused` | —；等待实质选择由歧义处理器表达，运行时暂停由 Execution 表达。 |
| `disabled` | 仅在源文本只读或当前策略禁止重新绑定时使用；显示原因和可检查入口。 |

## 5. 理解审阅

### 层级、位置和触发

- **层级归属：** Simple 主层；Inspection 查看完整 GoalPlan/TaskPlan 及版本关系；必要的 Source/歧义卡片在同一上下文临时插入。
- **位置：** 意图编辑器之后的理解摘要，仍然围绕“会产生什么结果”而不是配置字段。
- **触发：** 分析完成、源文本改变产生实质理解变化，或用户打开已有意图时出现。若没有可用理解，不渲染“空审阅”占位。

### 内容层级与交互

默认只列与当前意图相关的语义项，例如时间、数据、操作、无匹配输入时的策略、确认/介入。每项显示“我的理解”和必要的影响；详细规范化值和计划进入 `检查详情`。

- 无歧义时用户可以继续，接受不是重新填写表单。
- 实质歧义显示歧义处理器；缺失 Source 在数据项内显示 Source 连接卡片。
- 用户编辑自然语言后旧摘要标为过期，重新分析才生成新摘要；不得将旧摘要静默应用于新文本。
- `检查详情` 锚定到当前理解对象，关闭后回到编辑器和原焦点。

### 无障碍

- 使用语义标题、描述列表和可读标签；时间、数据、操作等标签不只用颜色区分。
- 理解变化用 `aria-live="polite"` 播报一次；实质歧义用关联错误/提示语义，不自动抢焦点到无关区域。
- 摘要在 200% 缩放下单列重排；可操作项有 44px 目标和键盘路径。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | 显示当前稳定的简洁理解；只有相关项出现，不填充未提供的默认值。 |
| `loading` | 显示正在理解的对象和可安全取消/返回；保留旧摘要但标记为过期，避免新旧混淆。 |
| `success` | 显示经过结构化校验的理解摘要；可继续到 Source/输入/运行，或进入检查。 |
| `failure` | 用普通语言说明无法完成理解、影响和下一步；将需要选择的部分交给歧义处理器，不伪装为已理解。 |
| `paused` | —；需要人工等待的运行时暂停不由理解审阅承担。 |
| `disabled` | 仅在分析依赖缺失或意图处于只读历史状态时使用；源文本和可查看的旧理解仍可访问，原因可读。 |

## 6. 歧义处理器

### 层级、位置和触发

- **层级归属：** Simple 的临时上下文层；Inspection 查看选择事件和候选影响；不属于 Execution。
- **位置：** 紧邻产生歧义的理解项，不打开全局问答面板。
- **触发：** 至少两个兼容解释会实质改变结果、数据、目的地、时间或安全性时。单一明确候选静默绑定，不显示处理器。

### 内容层级与交互

1. 复述含歧义的用户短语。
2. 每个选项用自然语言名称说明“选择它会发生什么”；最多呈现少量有界选项。
3. 说明当前阻塞的影响和一个明确的选择/保留原文动作。

用户可键盘选择、查看差异、取消或保留未解决状态。取消不会偷偷选择默认项；选择结果记录为当前理解事件，源文本仍保持可读。若选项会触发新的权限请求，先进入 Source 连接流程。

### 无障碍

- 使用有标题和说明的 `radiogroup`/列表语义；当前选项、影响和错误均可被读出。
- 焦点进入第一项或标题并在关闭后恢复；`Escape` 取消选择而不是确认。
- 用文字、选中标记和边框表达选择；不以颜色或位置暗示推荐答案。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | 显示有界选项并等待用户选择；不把任一选项预选为事实。 |
| `loading` | 重新检查候选与权限；暂时禁用提交，保留原歧义短语。 |
| `success` | 选择通过语义/策略检查并显示已选含义；处理器关闭，摘要保留结果，选择事件可检查。 |
| `failure` | 候选失效、仍有冲突或选择不被策略允许时，解释影响并要求重新澄清；不随机回退。 |
| `paused` | —；若歧义导致 Run 停止，执行进度显示暂停，处理器仍作为临时选择入口打开。 |
| `disabled` | —；如果无法选择，组件应显示可读的类型化阻塞原因，而不是没有响应。 |

## 7. Source 连接与权限选择器

### 层级、位置和触发

- **层级归属：** Simple 的临时上下文主层；在 InputBundle 预检期间可作为 Execution 上下文出现；Inspection 显示授权范围、版本/快照和变更历史。
- **位置：** 理解摘要中缺失 Source 的数据项，或当前 Run 的预检区域；不作为首次使用时的永久清单。
- **触发：** 引用的数据或能力没有兼容且已授权 Source，或用户明确要变更授权范围时。

### 内容层级与交互

1. 为什么现在需要访问、要支持的任务能力和语义 Source 名称。
2. 请求范围（例如所选文件夹/仓库）和默认只读权限；写入权限若未来存在必须独立说明。
3. OS 文件夹/仓库选择动作、取消/拒绝路径和连接后的范围摘要。

用户通过系统选择器明确授权。自然语言不能扩大范围；所选范围由 Source Manager 校验。授权后只显示语义名称和短范围确认，具体权限/版本从 `检查详情` 进入。取消或拒绝不会伪装为“已连接”。

### 无障碍与安全

- 连接卡片有可读标题、目的、范围和主要/次要按钮；系统选择器打开前把焦点放在说明，返回后恢复。
- 读取授权、拒绝、系统错误和范围不匹配均以文字说明，不能只显示锁形图标。
- 不在卡片、播报或日志中显示 Secret、session 或未必要的文件内容；远程/本地 Source 均遵守最小权限和默认只读。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | 显示请求原因、范围和“连接”操作；不预先打开选择器。 |
| `loading` | 显示正在打开选择器/检查授权的对象；防止重复提交，保留取消/返回。 |
| `success` | 只表示授权范围已保存且 Source 检查通过；显示语义名称与范围摘要，下一步仍需建立 InputBundle。 |
| `failure` | 拒绝、范围不匹配、Source 不可用或检查失败时说明影响和重试/改选；不扩大权限或使用旧授权冒充新授权。 |
| `paused` | —；需要用户授权时是上下文等待，不把授权本身称为运行时 Human Takeover。 |
| `disabled` | 权限策略、平台限制或当前历史版本只读时禁用连接动作，并说明可检查的原因。 |

## 8. InputBundle 预览

### 层级、位置和触发

- **层级归属：** Execution 主层；Simple 可显示“已准备本次输入”的短摘要；Inspection 显示不可变来源、选中路径/哈希和版本关系。
- **位置：** Source 解析和选择完成、Run 开始前的预览区域；若输入不影响当前动作，不强行显示。
- **触发：** 已完成 Source resolution、selection、binding 和校验，并且用户需要检查会影响结果的确切输入时。

### 内容层级与交互

- 首层显示文章/文件的可读名称、关键字段（如标题、正文摘要、封面）、Source 语义名称和快照时间/版本摘要。
- 用户可展开正文/图片预览，查看缺失项和选择规则影响；原始 hash、确切路径和 InputBundle 结构进入 Inspector。
- “继续”接受当前不可变 bundle，“返回/重新选择”创建新的预检路径。执行开始后不允许组件静默刷新 bundle；若 Source 改变，显示新 Run/重新 snapshot 的明确选择。
- 没有匹配内容时用 `SKIPPED`/无匹配原因表达，不把空预览当成功。

### 无障碍

- 预览图有替代文本或同等文字；正文展开/收起按钮有状态和范围。
- 每个输入字段有名称、来源语义和是否必需的文字；缺失 required input 关联到恢复动作。
- 预览加载和完成使用一次性状态播报；不把大段正文放入实时区域。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | —；没有可检查的 bundle 时不显示空卡片。 |
| `loading` | 显示正在解析/选择/冻结的输入和已知进度；不能在用户不知情时替换内容。 |
| `success` | 显示已创建且不可变的本次输入预览；它表示 bundle 完成，不表示目的地动作已成功。 |
| `failure` | 缺少必需输入、选择歧义、快照失败或内容过期时说明影响；提供返回、重选或按策略跳过/失败的路径。 |
| `paused` | 只有 Task/Goal policy 明确要求用户在执行前审阅输入时使用；显示等待审阅原因和继续/返回，不与发布确认混合。 |
| `disabled` | Source 未授权、权限不足或 bundle 已被历史 Run 锁定时禁用继续；显示原因和检查入口。 |

## 9. 确认卡

### 层级、位置和触发

- **层级归属：** Execution 的临时上下文；Inspection 查看确认策略、时间、输入版本和用户选择；不属于初始意图编辑。
- **位置：** 紧接不可逆动作之前，覆盖/嵌入当前 Execution 上下文而不跳到新顶层页面。
- **触发：** confirmation policy 要求确认，且目的地、确切输入和动作均已验证。登录/安全验证需要 Human Takeover，不用确认卡替代。

### 内容层级与交互

1. 明确动词和目的地，例如“发布这篇文章到某账号”。
2. 确切输入的可读摘要、不可逆影响和可取消边界。
3. `[取消]` 与 `[确认]` 两个显式动作；关闭、点击遮罩或 `Escape` 不等于确认。

在确认前重新检查 bundle、目的地和去重/幂等边界。确认记录为事件，不能直接渲染成功；之后仍需 Execution 的动作和后置条件验证。

### 无障碍

- 使用有标题的 dialog/alertdialog 语义，打开后焦点进入标题或安全的首个动作，关闭后回到触发点。
- 确认/取消标签说明后果；不可逆的主要动作不通过颜色或默认焦点诱导。
- 确认卡内容可通过键盘完整读取；状态变化仅播报一次。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | 等待用户明确确认或取消；显示当前仍有效的输入和目的地摘要。 |
| `loading` | 正在复核输入、策略、账号和去重边界；暂时禁用确认并说明对象。 |
| `success` | 仅表示用户的确认/取消事件已经记录；卡片关闭并移交 Execution，不能使用成功结果样式。 |
| `failure` | 输入、目的地、授权或策略在确认前发生变化时拒绝确认，要求回到预览/连接或安全停止。 |
| `paused` | —；等待用户本身由 `idle` 表示，执行暂停原因由执行进度表达。 |
| `disabled` | 当前 policy 不允许该动作、Run 已终止或缺少确认权限时禁用并说明原因。 |

## 10. 执行进度与恢复

### 层级、位置和触发

- **层级归属：** Execution 主层；Inspection 显示完整 Run 时间线、步骤证据和版本关系。
- **位置：** Run 开始后当前工作区的单一状态区；不是计数器墙、实时日志流或运维 Dashboard。
- **触发：** Run 进入准备、运行、验证、暂停或失败状态；终态移交结果摘要。

### 内容层级与交互

- 当前状态的一句解释和一个有意义的里程碑，例如“正在准备输入”“正在打开发布平台”“正在验证结果”。
- 当前可操作的动作：取消、确认、接管、等待重试或基于证据的恢复；不渲染策略未允许的“继续”。
- 失败时显示影响、最后有意义的检查点和 `检查详情`；详细 Step、错误类型、截图和脱敏事件进入 Inspector。
- 恢复操作在安全边界内可以重试/返回/重新 snapshot；不能从未知状态自动继续，也不能把恢复后未验证的状态显示成功。

### 无障碍

- 使用单一 `aria-live="polite"` 播报里程碑；只有需要立即行动的安全暂停才使用一次 `assertive`。
- 进度条若使用，必须有文字名称、当前阶段和确定/不确定说明；不能只用旋转图形。
- 暂停和失败焦点移到原因和第一项安全动作；取消/恢复后焦点保持可预期。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | Run 已接收但尚未执行时显示“准备中”的最小状态，不显示空时间线。 |
| `loading` | 显示当前有意义里程碑和可安全取消；不滚动显示每一个内部 Step。 |
| `success` | 只有后置条件/目标结果已验证才显示完成，并移交结果摘要。 |
| `failure` | 显示类型化但面向人的原因、影响、检查入口和允许的恢复；保留最后成功检查点。 |
| `paused` | 明确是确认、Human Takeover、重试等待或安全暂停中的哪一种；说明恢复条件，不伪装空闲或成功。 |
| `disabled` | 只能查看、取消窗口已关闭或恢复被策略禁止时，禁用对应动作并说明原因；状态本身仍可读。 |

## 11. Human Takeover

### 层级、位置和触发

- **层级归属：** Execution 的临时上下文主层；Inspection 查看接管原因、时间、交还和重新验证证据。
- **位置：** 当前 Run 的安全暂停区域，保留真实浏览器上下文；不打开隐藏的“绕过”控制面板。
- **触发：** `LOGIN_REQUIRED`、`QR_REQUIRED`、`CAPTCHA`、`MFA_REQUIRED`、`SECURITY_CHALLENGE`、`ACCOUNT_WARNING`、同意/权限判断或不明确的破坏性动作需要用户操作时。

### 内容层级与交互

1. FlowPilot 识别的原因和对 Run 的影响。
2. 用户要在真实上下文中做什么（登录、扫码、确认同意或手工判断）。
3. FlowPilot 在交还后会验证什么，以及不可安全验证时会怎样停留。

用户可以打开/操作受隔离的浏览器上下文并明确“交还控制”。交还不是成功；runtime 必须重新 snapshot、检查已知安全状态和后置条件后才恢复。不得提供 CAPTCHA/MFA 绕过、隐藏 webdriver、伪造指纹或其他规避控制的动作。

### 无障碍与安全

- Takeover 区域有清晰标题和暂停播报；焦点进入 FlowPilot 的说明/交还控件，不强行把屏幕阅读器焦点注入不可信网页。
- 远程页面保持隔离，FlowPilot 的说明层与网页视觉/语义分开；Secret 输入留在授权的真实页面，不复制到普通 UI、日志或 prompt。
- 用户交还后显示“正在重新验证”，只有验证成功才允许下一个动作；未知/不安全状态提供停止或继续人工处理，不自动恢复。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | —；没有需要人工操作的风险时不显示 Takeover 框架。 |
| `loading` | 正在打开/连接安全浏览上下文或整理脱敏状态；说明对象，不让运行静默前进。 |
| `success` | 只表示用户已交还控制且交接事件被记录；立刻进入重新验证，不显示 Run 成功。 |
| `failure` | 用户操作后状态未知、验证失败、页面被替换或安全策略不允许恢复时，保持暂停并给出停止/重新接管路径。 |
| `paused` | 等待用户操作、扫码、登录、同意或判断；显示明确原因、可做动作和交还条件。 |
| `disabled` | 当前环境不允许安全接管或策略要求停止时禁用交还/继续，并说明人工支持路径；不提供绕过按钮。 |

## 12. 结果摘要与 `检查详情`

### 层级、位置和触发

- **层级归属：** Simple 的终态主层；Execution 从进度收尾进入；Inspection 是其上下文详情。
- **位置：** Run 的当前来源工作区，不新建永久“结果 Dashboard”。
- **触发：** Run 经过结果验证并进入 `SUCCEEDED`、`SKIPPED`、`FAILED` 或 `CANCELLED` 等终态，或用户从当前状态主动查看结果。

### 内容层级与交互

- 第一行明确“发生了什么”和结果对象；第二行说明影响/下一步；有证据时提供 `检查详情`。
- `SUCCEEDED` 仅用于经过后置条件验证的结果；`SKIPPED` 使用中性/信息样式和明确原因（如没有匹配内容），不能用成功绿色；失败/取消保留类型化影响和可操作下一步。
- `检查详情` 锚定到本次 Run 的确切版本/输入/结果，不静默切换到最新计划。关闭后回到结果并恢复焦点。
- 默认不显示每一步、原始日志、截图或哈希；需要解释时进入 Inspector 的相应分区。

### 无障碍

- 结果标题、状态文字和下一步形成语义区域；图标和颜色只是冗余线索。
- 终态变化通过 `aria-live="polite"` 播报一次；失败的修复动作通过描述关联。
- `检查详情` 是有文字的可操作入口，不能只用齿轮/眼睛图标。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | —；没有终态或当前 Run 时不显示结果卡片。 |
| `loading` | 显示正在验证结果的短状态，不提前显示成功/失败。 |
| `success` | 显示已验证成功的最小结果和 `检查详情`；不将确认事件或动作点击当成成功。 |
| `failure` | 显示失败/取消的影响、最后已知状态和允许的下一步；保留检查入口。 |
| `paused` | —；未终态的暂停由执行进度/Takeover 组件显示。 |
| `disabled` | 仅在结果证据被权限/脱敏策略限制时禁用细节入口；摘要仍说明“详情不可用”的原因。 |

### 特殊终态：`SKIPPED`

`SKIPPED` 不是上述六种 UI 状态中的 `success`。结果摘要必须以中性信息样式说明跳过原因和是否需要用户操作；例如“今天没有匹配内容，未发布”。对应的选择/Source 证据仍可从 Inspector 检查。

## 13. Inspector 外壳与分区

### 层级、位置和触发

- **层级归属：** Inspection 主层；从 Simple/Execution 中某个陈述、对象、结果或失败的 `检查详情` 进入。
- **位置：** 保留来源上下文的侧栏、抽屉或同上下文面板；不成为永久顶层目的地。
- **触发：** 用户主动检查，或恢复必须显示特定证据才能理解；进入时带有明确锚点和确切对象/版本。

### 分区顺序与内容层级

Inspector 从结构化、可读事实开始，按需深入原始且已脱敏证据。默认只打开与入口相关的分区；其余折叠且不进入普通 Tab 顺序。

1. **源文本与理解**：用户 Goal/Task 文本、当前简洁理解、语义绑定；保留用户文本和编译结果的区别。
2. **时间与策略**：解释后的日程/时区、选择规则、确认/介入策略；普通路径不显示 cron。
3. **Source 与授权**：语义 Source 名称、显式授权范围、只读能力、快照/版本摘要；内部权限细节按需查看。
4. **InputBundle**：本次 Run 的不可变输入、选中内容摘要、来源路径/哈希（按需）、创建时间。
5. **Flow 与 Run**：确切 Flow 修订、当前 Run 绑定、可读的步骤/里程碑、状态和版本关系。
6. **证据**：后置条件、截图/页面状态（已脱敏）、状态变化和结果验证；原始事件/日志进入更深层。
7. **修复差异**：旧/新 Flow 修订、有界差异、影响、校验和用户决定；不默认打开完整工作流编辑器。

内部 ID、序列化计划字段和精确机器值只在用户明确展开技术详情时出现，并保持与人类可读名称并列；它们永远不是普通路径的前置条件。Inspector 不能静默读取当前 Source 的新内容替换已绑定快照。

### 交互与无障碍

- 外壳有标题、当前锚点、关闭/返回动作和可见焦点；关闭恢复触发 `检查详情` 的按钮或链接。
- 分区使用可折叠的标题和 `aria-expanded`/`aria-controls` 等价语义；键盘可顺序展开/收起。
- 结构化表格需要列标题和移动端/高缩放重排；差异/哈希区域可以在标注的容器中横向滚动。
- 证据与错误关联到解释它们的陈述；不把整段原始日志作为唯一可理解说明。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | —；未打开 Inspector 时不保留空侧栏。 |
| `loading` | 显示正在加载哪个确切对象/版本；先显示外壳和锚点，避免焦点跳到未关联内容。 |
| `success` | 以分区提供与入口相关的结构化事实、证据和版本关系；深层内容按需展开。 |
| `failure` | 说明详情不可加载、已被脱敏或版本不存在；保留可见的摘要和安全下一步，不显示半真半假的数据。 |
| `paused` | 当前 Run 暂停时突出暂停原因、最后成功检查点和允许恢复；不得把 Inspector 本身的打开状态当成继续执行。 |
| `disabled` | 因权限/脱敏策略不能查看某分区时显示原因和可用替代事实；不渲染无意义的空字段。 |

## 14. 证据查看器

### 层级、位置和触发

- **层级归属：** Inspection 分区；从结果、失败、InputBundle 或后置条件进入，不单独作为导航目的地。
- **位置：** Inspector 的“证据”区或由某条状态说明锚定打开。
- **触发：** 用户需要验证“用了什么输入”“是否达到目标状态”“为什么暂停/失败”时；普通路径只显示可读结论。

### 内容层级与交互

- 先显示证据类型、对应断言/后置条件、时间和结论；再按需展开脱敏截图、页面状态、输入来源或状态变化。
- 清楚区分用户源文本、确定性 runtime 事实、平台返回状态和 AI 派生内容。证据不可静默更新到另一 Run。
- 页面截图有说明和替代文本；原始事件、网络细节和日志只有在用户进一步展开且已经脱敏时出现。

### 无障碍

- 每个证据条目有标题、类型、时间、结论和关系说明；图片提供替代文字，视觉差异提供文字摘要。
- 展开/收起、返回和复制（若适用）均有可读名称；复制不得把 Secret 或未脱敏内容带入普通剪贴板。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | —；没有被检查对象时不显示证据查看器。 |
| `loading` | 显示正在取得哪个已脱敏证据；不以占位内容代替最终结论。 |
| `success` | 显示与当前 Run/版本关联且可解释的证据；成功结论仍来自验证规则。 |
| `failure` | 证据缺失、加载失败或脱敏后不足以证明结论时诚实说明；不由截图缺失推断成功。 |
| `paused` | 当证据表示安全状态未知/等待人工时，显示暂停和需要完成的验证；不自动向下执行。 |
| `disabled` | 权限、Secret 或安全策略禁止查看时说明“为何不可查看”以及可用的摘要；不暴露被保护内容。 |

## 15. 修复差异

### 层级、位置和触发

- **层级归属：** Inspection 主层；必要时从 Execution 的可恢复失败卡片打开临时上下文，但不让修复编辑器占据黄金路径。
- **位置：** 与失败 Step、最后成功检查点和受影响目标相邻；Inspector 中以修复分区呈现。
- **触发：** Repair 提议已经通过 schema/policy 边界检查，且行为变化需要用户评审、跨越策略边界或用户主动要求比较时。无实质变化且安全的局部修复仍保留证据，但不强制完整差异 UI。

### 内容层级与交互

1. 失败影响、最后成功检查点和提议将解决什么问题。
2. 旧/新可读路线或行为的最小差异，以及输入/权限/确认影响。
3. 验证状态、是否通过有界试运行、接受/保留旧版本的明确选择。

差异必须是局部且有界的；不得默认暴露 selector、模型 prompt、完整原始 Workflow DSL 或不相关步骤。接受修复创建新的 immutable Flow revision，保留旧 revision；拒绝/关闭不覆盖旧版本。页面内容不能修改 hard-stop safety policy。

### 无障碍

- 使用“旧行为/新行为”明确标题和文字化差异；增加/移除/修改不能只用绿/红色或删除线表达。
- 接受、保留旧版本、取消和 `检查详情` 有清晰后果文案；焦点在关闭后恢复到失败卡片/来源。
- 试运行、校验和安全阻塞作为状态文字播报一次；未知状态不提供自动接受。

### 状态行为

| 状态 | 行为 |
| --- | --- |
| `idle` | —；没有需要比较的提议时不显示差异查看器。 |
| `loading` | 显示正在校验或生成有界差异的对象；不展示未经校验的候选作为可接受事实。 |
| `success` | 只表示提议通过 schema/policy 校验并且差异证据可查看；是否真正采用由用户决定，不能显示 Run 成功。 |
| `failure` | 无效、不安全、超出范围或试运行失败时说明影响，保留旧 Flow，提供停止/返回/重试检查路径。 |
| `paused` | 等待用户评审或安全边界决定时暂停；显示旧/新差异和继续条件，不自动接受。 |
| `disabled` | hard-stop 策略、权限或证据不足时禁用接受；仍可查看失败原因和保留旧版本。 |

## 16. 组件契约评审清单

实现或组合组件前，Reviewer 必须能从本文件回答：

1. 组件的主层级是什么，当前事件为什么让它出现，解决后是否消失？
2. 普通路径是否仍只使用自然语言和语义名称，内部 ID、DSL、cron、selector、工作流节点和原始日志是否留在 Inspection/技术详情？
3. 组件是否清楚区分 `idle`、`loading`、已验证 `success`、`failure`、`paused` 和 `disabled`，且未为不适用状态制造空 UI？
4. 所有涉及 Source、InputBundle、确认、接管、恢复和修复的动作是否保留显式安全边界与证据路径？
5. 键盘、焦点恢复、屏幕阅读器播报、200% 缩放、对比度和减少动态效果是否能完成同一目标？
6. `检查详情` 是否锚定到当前对象和确切版本，关闭后是否回到来源上下文？

本文件只定义组件契约；具体屏幕顺序、布局和黄金流程由后续 `SCREEN-SPECS.md` 与 `FLOWS.md` 定义，不得借此文件提前实现 P0 或运行时功能。
